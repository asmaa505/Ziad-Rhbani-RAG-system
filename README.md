# 🎹 Ziad Rahbani RAG System 

نظام ذكاء اصطناعي يعتمد على تقنية **RAG (Retrieval-Augmented Generation)** للإجابة على الاستفسارات، تحليل النصوص، واستخراج المعلومات الخاصة بالإرث الفني والفلسفي للفنان العبقري **زياد رحباني**.

---

## 🚀 نظرة عامة على المشروع (Project Overview)
يهدف هذا المشروع إلى بناء قاعدة معرفية (Knowledge Base) شاملة ومحرك بحث ذكي قادر على فهم أسلوب زياد رحباني، مسرحياته، عباراته الساخرة، وموسيقاه، والإجابة على أسئلة المستخدمين بناءً على مصادر موثوقة ومجمعة بدقة، بدلاً من الاعتماد على الهلوسة البرمجية للنماذج اللغوية الكبيرة.

---

## 📊 هيكل البيانات ومصادرها (Data Sources & Pipeline)
جمع وتصنيف الداتا لتشمل كافة الجوانب الفنية والشخصية:

*   **🎙️ اللقاءات والحوارات:** المقابلات التلفزيونية والإذاعية.
*   **📻 البرامج الإذاعية:** البرامج الشهيرة مثل *"العقل زينة"* و*"تابع لشي تابع"*.
*   **🎭 المسرحيات:** (*سهرية، نزل السرور، بالنسبة لبكرة شو؟، فيلم أمريكي طويل، شي فاشل، بخصوص الكرامة والشعب العنيد، لولا فسحة الأمل*).
*   **🎵 الأغاني والألبومات:** الأغاني (التي غناها أو لحنها لـ فيروز، جوزيف صقر، وغيرهم) مع الميتا-داتا الخاصة بكل ألبوم.
*   **📝 المقالات الصحفية:** الأرشيف المكتوب لزياد في الصحف والمجلات.
*   **🎬 الأفلام والوثائقيات:** الأعمال السينمائية والدراسات والبرامج الوثائقية التي تناولت مسيرته وتحليل ظاهرة زياد رحباني.

---

## 🛠️ بنية النظام الهندسية (System Architecture)

ينقسم المشروع إلى 3 مراحل رئيسية:
1. **تجهيز وتجزئة النصوص (Chunking):** قراءة البيانات الفنية المصنفة في صيغة JSON وتجزئتها لقطع نصية جاهزة للفهرسة.
2. **توليد وتخزين المتجهات (Embedding & Vector DB):** تحويل النصوص إلى متجهات رقمية باستخدام نموذج `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` متعدد اللغات، وتخزينها في قاعدة بيانات متجهة مستمرة **ChromaDB**.
3. **توليد الإجابات (RAG Generation):** استرجاع النصوص ذات الصلة بالسؤال من ChromaDB، ودمجها في Prompt مخصص، ثم إرسالها لنموذج **Gemini 3.5 Flash** لتوليد إجابة طبيعية ودقيقة باللغة العربية.

## 📋 المتطلبات البرمجية (Prerequisites)

يرجى تثبيت المكونات التالية في بيئة العمل الخاصة بك:
```bash
pip install chromadb sentence-transformers google-genai python-dotenv truststore
```

*ملاحظة: تم دمج مكتبة `truststore` لحل مشاكل فشل التحقق من شهادات SSL على نظام التشغيل Windows أثناء تحميل النماذج من Hugging Face.*

---

## ⚙️ الإعداد والتشغيل (Setup & Execution Guide)

### 1. إعداد مفتاح API
قم بإنشاء ملف `.env` داخل مجلد `RAG Generation` وأضف مفتاح Gemini API الخاص بك:
```env
GEMINI_API_KEY=your_gemini_api_key_here
```

### 2. بناء قاعدة البيانات المتجهة (Vector Database)
لتحميل النصوص والبيانات الفنية وتخزينها كمتجهات في ChromaDB، قم بتشغيل:
```bash
python Embedding/buildDB.py
```

### 3. اختبار عملية البحث (Retrieval Test)
لاختبار جودة استرجاع المعلومات من قاعدة البيانات المتجهة دون استدعاء نموذج التوليد:
```bash
python Embedding/query.py
```

### 4. تشغيل نظام الـ RAG الكامل (Generate Answer)
لطرح سؤال وتوليد إجابة ذكية دقيقة مدعومة بالسياق التاريخي والفني من الأرشيف باستخدام Gemini:
```bash
python "RAG Generation/generate.py"
```

## 🔍 المشاكل الشائعة وحلولها (Troubleshooting & Errors Solved)

خلال إعداد وتشغيل النظام، قد تواجه بعض الأخطاء البرمجية الشائعة المتعلقة بالبيئة أو الإصدارات، وإليك تفاصيلها وكيفية حلها:

### 1. خطأ التحقق من شهادة الأمان (SSL: CERTIFICATE_VERIFY_FAILED)
*   **المشكلة:** عند تشغيل موديول التحويل المتجه (Embedding) ومحاولة تحميل نموذج اللغة من Hugging Face، يظهر خطأ:
    ```text
    [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: unable to get local issuer certificate (_ssl.c:1081)
    ```
*   **السبب:** نظام تشغيل Windows أو جدار الحماية يمنع بايثون من الاتصال بـ Hugging Face بسبب عدم التعرف على شهادات الأمان المحلية.
*   **الحل:** تم حل المشكلة عن طريق استخدام مكتبة `truststore` التي تجبر بايثون على استخدام مخزن الشهادات الرسمي لنظام التشغيل Windows بدلاً من الاعتماد على شهادات بايثون الافتراضية. نقوم باستدعائها في السطر الأول من الكود كالتالي:
    ```python
    import truststore
    truststore.inject_into_ssl()
    ```

### 2. خطأ تعذر العثور على النموذج (404 NOT_FOUND - Gemini Deprecation)
*   **المشكلة:** يظهر الخطأ التالي عند استدعاء واجهة برمجة تطبيقات Gemini لإنتاج الإجابات:
    ```text
    google.genai.errors.ClientError: 404 NOT_FOUND. {'error': {'code': 404, 'message': 'This model models/gemini-2.5-flash is no longer available to new users...'}}
    ```
*   **السبب:** تقاعد نموذج `gemini-2.5-flash` وعدم إتاحته للمفاتيح والمشاريع الجديدة التي تم إنشاؤها حديثاً.
*   **الحل:** تم تغيير اسم النموذج المستخدم في كود التوليد بملف `generate.py` إلى نموذج الجيل الجديد الأكثر استقراراً ودعماً: `gemini-3.5-flash`.
